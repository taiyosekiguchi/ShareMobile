# Threads AI自動運用システム — 設計概要

## 目的

Threads（Meta）アカウントをAIエージェントで完全自動運用し、アフィリエイト収益を得るシステム。
1日の人間作業ゼロで投稿・分析・改善サイクルを回す。

---

## なぜThreadsか

| SNS | 課題 |
|-----|------|
| X (Twitter) | フォロワーがいないと拡散しない |
| Instagram | リール（動画）必須 |
| TikTok | 動画編集必須 |
| **Threads** | **テキストのみ・フォロワー0でもバズれる** |

- アルゴリズムがフォロワー外にも積極拡散
- テキストのみ → AI生成と最も相性が良い
- 完全自動化が最も現実的なプラットフォーム

---

## ツール: Claude Code

ターミナル上で動くAIエージェント実行環境。

- **普通のAIチャットとの違い**: ファイル操作・コマンド実行・ブラウザ操作が可能
- **シェルスクリプト・cronと連携**できるため、既存の自動化インフラと統合しやすい
- 「AIに考えてもらう」ではなく「**AIに働いてもらう**」

## システム構成: 6つのAIエージェント

### 設計原則: 1エージェント = 1タスク

複数タスクを1エージェントに集中させると精度が落ちるため、役割を分離する（人間の会社組織と同じ発想）。

---

### エージェント①: リサーチャー（ネタ収集）

**役割**: YouTube・Xからキーワードでネタをリサーチし、JSONに構造化して保存

**仕組み**:
- 事前に「テーマツリー」を定義（例: 転職準備 > 面接攻略 > 年収交渉）
- テーマツリーを参照して「ネタが不足しているカテゴリ」を自動判断
- YouTube動画を検索 → 文字起こしを取得 → 使えるネタだけ抽出

**出力**: 構造化されたネタJSON

---

### エージェント②: アナリスト（パフォーマンス分析）

**役割**: 過去投稿のデータを分析し、ライターへの改善指示書を生成

**入力**: フェッチャーが取得した閲覧数・いいね数・リプライ数

**出力**: 次のバッチへのフィードバック指示書（例: 「断言型1行目が伸びてるので増量」「エージェント批判系は飽きられてるので控える」）

**ポイント**: AIがAIにフィードバックを出す自律改善ループ

---

### エージェント③: ライター（投稿生成）← メインエンジン

**役割**: リサーチャーのネタ + アナリストのフィードバックを元に投稿を生成

**1バッチあたり**: 5〜10本を一気に生成

**生成ルール**:

1. **投稿パターン15種類以上**をローテーション
   - 短文完結 / コメント誘導型 / ツリー展開型
   - 各タイプに「暴露系」「需要確認型」「リスト系」などサブカテゴリ
   - 直近3件で使ったパターンは使用禁止（自動ローテーション）

2. **1行目パターン集** (265件以上のバズ投稿から収集)
   - 構造のみを学習して自ジャンルに変換して使用

3. **自己採点（10項目 × 各10点満点）**
   - フックの強さ / 有益性 / 具体性 / テンポ感 / ペルソナ一致度 など
   - **平均7.0未満 → 書き直し**（最大2回）
   - 2回書き直してもNG → 棄却

4. **類似度チェック**
   - 過去100件と比較して類似度0.85以上 → 棄却

**出力**: 投稿キュー（JSON）

---

### エージェント④: ポスター（投稿実行）

**役割**: キューの投稿をThreads APIで自動投稿

**スケジュール**: cronで1日10スロット（朝8時〜深夜1時、約2時間おき）

**投稿タイプ別の挙動**:
- コメント誘導型 → 本文投稿後、コメント欄に続きを自動書き込み
- ツリー型 → 返信で繋げていく
- アフィリエイト投稿 → コメント欄にPRリンクを自動配置

---

### エージェント⑤: フェッチャー（データ取得）

**役割**: 投稿の24時間後にメトリクスを自動取得し、投稿履歴に追記

**取得データ**: 閲覧数 / いいね数 / リプライ数

**重要性**: このデータがないとアナリストが機能しない（改善サイクルの起点）

---

### エージェント⑥: スーパーバイザー（監視・緊急停止）

**役割**: システム全体の異常検知と緊急停止

- エラー3回連続 → 自動停止
- 投稿が予定通り実行されていない → 通知
- **KILL_SWITCH**: 全アカウントの投稿を即時停止できる緊急スイッチ

---

## 日次の自動サイクル（人間の操作は起動のみ）

```
シェルスクリプト1個を手動実行
    ↓
フェッチャー: 昨日の投稿データを取得
    ↓
アナリスト: データを分析し指示書を生成
    ↓
リサーチャー: テーマツリーを確認しネタ補充
    ↓
ライター: 10本の投稿を生成・採点・キューに投入
    ↓
ポスター: cronで2時間おきに1本ずつ投稿（自動）
```

## 設計の4原則

### ① エージェント分離
1エージェント = 1タスク。混在させない。

### ② ナレッジとロジックの分離
口調・NGワード・投稿パターン・ターゲット情報は**外部ファイルに切り出す**。
コードに人格をハードコードしない。

→ ナレッジファイルを差し替えるだけでジャンル変更（転職 → 美容 → ママ向けなど）が可能。新アカウント追加もテンプレートコピー + ナレッジ記述のみ。

### ③ 状態管理
投稿履歴・キュー・読者分析をすべて**JSONで永続管理**。
これがないと毎回ゼロから生成になり、同じ投稿をループし続ける。

### ④ 安全装置（多層ガード）
| ガード | 条件 |
|--------|------|
| 品質スコア | 7.0未満 → 棄却 |
| 類似度 | 0.85以上 → 棄却 |
| 投稿上限 | 1日15件まで |
| 最低間隔 | 投稿間隔1時間以上 |
| 緊急停止 | KILL_SWITCHで即停止 |

> 「AIに任せる」と「AIを放置する」は別物。手綱は必ず握る。

## 失敗事例（重要な教訓）

### 事故①: 1分で10連投 → アカウント凍結

**原因**: 投稿間隔設定ミス。AIの処理速度をそのまま使用。

**Threads側の判断**: botと判定 → 凍結

**教訓**:
> **AIの速度をそのまま使うな。人間のリズムに合わせろ。**

**対策**: 最低1時間間隔 + 1日10スロットに分散（朝8時〜深夜1時）

---

### 事故②: 同じ投稿を30回ループ

**症状**: 「転職エージェントに騙されるな」系の投稿が表現を変えながら30回繰り返された

**原因**: 類似度チェックなし。AIは「最適解」を毎回出し続けるが、人間のように「飽きた」と感じない。

**教訓**:
> **AIは放っておくと最適解に収束する。同じ最適解を永遠に出し続ける。**

**対策**:
- 過去100件と類似度比較（0.85以上は棄却）
- 直近3件と同じ構造パターン禁止
- 15種類以上のパターンを強制ローテーション
- 同じテーマ3回連続で別テーマに自動切替

## 収益化の方法

- **ASPアフィリエイト**（商品作成不要）
- 投稿本文は普通の有益コンテンツ
- コメント欄にさりげなくPRリンクを配置
- ライター（本文）+ ポスター（リンク配置）が自動で対応

---

## 現在の運用状況

- **3アカウント並行運用**（転職・美容・ママ向け・SNS運用 等）
- ナレッジファイル差し替えのみでジャンル切替可能
- **バズピボット**: バズった投稿から関連投稿を3本自動派生生成
- 読者コメントを分析して次の投稿テーマに自動反映
- KILL_SWITCHで全アカウント即停止可能
- **人間の作業**: 戦略判断のみ（方向性・ナレッジ追加の意思決定）

## Claude Codeへの実装ヒント

このシステムをClaude Codeで実装する際の要点:

```
プロジェクト構造（例）
threads-auto/
├── agents/
│   ├── researcher.py      # リサーチャー
│   ├── analyst.py         # アナリスト
│   ├── writer.py          # ライター
│   ├── poster.py          # ポスター
│   ├── fetcher.py         # フェッチャー
│   └── supervisor.py      # スーパーバイザー
├── knowledge/             # ナレッジ（ジャンル別に切替可能）
│   ├── account_persona.json
│   ├── ng_words.json
│   ├── post_patterns.json
│   ├── target_audience.json
│   └── theme_tree.json
├── data/                  # 状態管理（永続化）
│   ├── post_history.json  # 投稿履歴（類似度チェック用）
│   ├── post_queue.json    # 投稿キュー
│   └── analytics.json     # パフォーマンスデータ
├── hooks/                 # 1行目バズパターン集
│   └── first_line_patterns.json  # 265件以上
├── run_daily.sh           # 日次起動スクリプト
└── cron_poster.sh         # cronで定期実行する投稿スクリプト
```

**実装時の注意点**:
1. Threads API認証情報は環境変数で管理
2. 各エージェントは独立して実行できるよう設計
3. エラー発生時はスーパーバイザーが検知してログに記録
4. 状態ファイル（JSON）はエージェント間の唯一の通信手段
5. 品質スコア計算はライター内に関数として実装
6. cronタブに `cron_poster.sh` を登録して自動投稿
